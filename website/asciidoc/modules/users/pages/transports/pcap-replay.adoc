= PCAP Replay

Replays a previously recorded PCAP or PCAPNG capture as if it were a live device. Nothing is sent
to a network: the driver connects, and the frames it "receives" come out of the file.

This is a debugging and development transport. It is what lets you work on a driver against a
capture taken from a machine you cannot reach, and it pairs naturally with the
xref:audit-log.adoc[audit-log] - record once, then replay as often as you need.

== Transport syntax

The capture is named by the `pcap-replay.pcap-file` parameter; the address segment of the
connection string is not interpreted.

.Example
[source]
----
profinet:pcap-replay://?pcap-replay.pcap-file=/tmp/line-3.pcapng&pcap-replay.speed-factor=1.0
----

include::partial$transport-pcap-replay.adoc[]

Two options are worth knowing before the first run:

* `pcap-replay.speed-factor` defaults to `0`, which replays the capture as fast as it can be read.
  Set it to `1.0` to reproduce the original timing - which is what you want when the bug you are
  chasing is a timing one.
* `pcap-replay.only-incoming-packets` defaults to `true`, so by default only the frames the device
  sent are replayed and the driver's own requests go nowhere. That is the right setting for
  standing in for a device.
